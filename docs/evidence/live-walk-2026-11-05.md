# Live stranger walk — 2026-11-05

What a person who has never opened Dossier gets. Chromium (Playwright 1.64.1) against a
real `dossier serve` on `127.0.0.1:8077`, over a **copy** of the owner's real workspace
(`<workspace>` → `%TEMP%/dossier-live-2026-11-05`, 244
entries, 728 indexed files, 23 archived postings). The owner's folder was never written to.

Walk script: `~/.dsh/scratch/dossier-live-2026-11-05/walk.py` (committed nowhere; it is a
receipt, not a gate). Raw numbers: `receipts/walk.json`. Screenshots: `receipts/live-*.png`.

## Two defects the walk found, both fixed in this session

**1. A pane had no address.** `pane` was React state only. Loading
`http://127.0.0.1:8077/` and clicking Papers → Verify, then pressing reload, put the person
back on Folder — measured before the fix: `after_reload_h1 = ["Put the folder on the light
table."]`, URL unchanged. The same made Back leave the app and nothing shareable or
bookmarkable exist.

Now each pane is `#/<area>/<pane>` through `history.pushState`, restored on load and by
`popstate`. Measured after: cold load of `#/papers/verify` → **h1 `Verify`**, active pane
`Verify`, active area `Papers`; Back from Search → **h1 `Jobs`**. Tests:
`test_a_pane_has_an_address_that_survives_a_cold_load`,
`test_the_back_button_moves_between_panes`.

**2. The landing pane hid the reason the workspace was blocked.** The engine already knew
one next unit and two blockers (`/api/agent/status`), but the welcome screen was a file
browser with a sentence. On this real workspace the app is blocked — measured:
`"No base .docx in this folder. Document generation is blocked: layout cloning needs a real
user document; there is no template fallback."` — and nothing on the landing pane said so.

Now `NextStep` renders it with one button that opens the pane that fixes it. Measured after:
`Waiting on you: Build / Open Build / No base .docx in this folder… / 728 files · 23
postings`. Test: `test_the_landing_pane_names_the_next_unit_of_work`.

## What is still friction, measured and not fixed

- **748 buttons** exist in the shell at once (the explorer renders all 728 files). Only one
  is a tab stop (roving `tabindex`), so this is a render cost, not an a11y trap — but no
  virtualisation exists.
- **Jobs renders 172 KB of text** in one pane; nothing paginates it.
- **The bundle rail shows "Select a file first."** in every pane until a file is chosen;
  it is correct and it is the first thing a stranger reads next to a real pane.
- **`dossier serve` prints a bare URL and every other route is 401 without the cookie** —
  correct by design (the token never travels in a URL), but a person who copies the API
  URL into a browser tab gets `Unauthorized` with no next step.

## Not checked

The screenshots were taken, not looked at by a person or a vision model in this session, so
no claim here is about appearance — every number above is read from the DOM or the network.
`contrast` and `target size` were not re-measured by the walk itself. They were re-measured
separately on the new build, and `.ui-ux-master/measure.py` reports **0** for headings,
contrast, sub-24 px targets, unnamed controls and overflow at 1440/768/390, **0** dark-theme
contrast failures, 30/30 focus stops ringed. (Its `console: 33` is the instrument's own
Canvas2D readback warning from sampling colours, not an app message — the walk's own console
listener recorded 0 errors and 0 warnings.)
