# The first relevance measurement — 2026-11-05

`score_job` has been arithmetic for weeks and `rank_corpus` has sorted on it, but nothing on
this machine ever said whether that order was right. On the only real run 554 rows scored
**0 strong / 12 possible / 542 unlikely** and no row carried a human grade. This is the first
receipt with labels behind it.

## The instrument

```text
dossier identity labels --root <ws> [--out FILE] [--limit N]
dossier identity eval   --root <ws> --labels FILE [--k 10] [--source auto|postings|corpus]
                        [--baseline FILE] [--write-baseline FILE]
```

`labels` writes a worksheet: every row scored, `earned`/`available` and `reasons[]` beside
it, and `grade: null` until a person writes one. The one exception is the tracker's own `Fit`
column, which is the owner's judgement recorded earlier; it is carried onto a posting only
when the employer matches and at least two role tokens do, and it is marked
`source_of_grade: tracker` so every report can separate it from a fresh grade.

`eval` reports, over the rows it could match:

| metric | what it says |
|---|---|
| `nDCG@k` | graded agreement, judged rows only, ideal order as reference |
| `precision@k` | of the judged rows in the product's first k, the share worth applying to |
| `precision_slots` | of the **k rows the app actually shows**, the share worth applying to — an ungraded row is a miss |
| `recall@25` | share of all "worth applying" rows that reached the first 25 |
| `spearman` | does a higher score mean a better grade, over every graded row |
| `baseline_arrival` | the same five numbers for the order the rows arrived in, so an improvement is a comparison |

Gate `fit-is-measured` fails the command when `nDCG@k` or Spearman drops past
`evaluation.NDCG_SLACK` / `SPEARMAN_SLACK`, and also when the labelled set shrank by more
than half (a metric on a smaller set is not comparable).

## What this receipt does **not** say

**The labelled set is a biased positive sample.** The tracker records the roles the owner
chose to tailor a document for, so `Fit` is High or Medium and nothing is Low or Skip:
`strong 5, possible 13, unlikely 0, skip 0`. A ranker is not challenged by a set with no
irrelevant rows, which is exactly why `P@10` is 1.0 for both orders — it cannot discriminate.
The discriminating numbers are Spearman (**0.5011** vs **-0.3945**: the score does carry the
owner's judgement at a rank level) and `precision_slots`, where the product **loses** (0.80
against 1.00) because 2 of its top 10 rows are rows nobody graded.

**`n=18` is small.** An 18-row Spearman has a wide interval; the instrument reports it
rather than pretending a point estimate is a result. The comparison is also 23 rows deep,
not 554: the archived postings are the only listings whose text the app captured itself.

**The corpus is not the shortlist.** `/api/agent/status` on this workspace reports 23
postings and no current capture, so `--source postings` (the default) is what ran. Running
`--source corpus` needs a fresh `dossier feeds fetch` + `corpus build`; that is the same 554
rows as before, and it would still have no grades.

## The number that would make this a benchmark

200 hand grades, of which at least 60 are `unlikely` or `skip`, spread over the **top and
bottom** of the product's own order (pool the top 10 and the bottom 10 first — labelling the
middle changes nothing). Then nDCG@10 ≥ 0.80 on a held-out 40 and a response-rate-by-band
table with non-overlapping 95% CIs after ~100 real applications. Today: 18 prior grades,
0 outcome events (`job-history.md` status is `drafted` for all 38 rows, so there is no
applied/responded pair anywhere on this machine).
